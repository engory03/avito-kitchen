# Стыки фич

## Заказ

1. Можно вызвать проверку корзины — без создания заказа.
2. Потом создание заказа.
3. При создании:
   - смотрим ключ идемпотентности;
   - ещё раз проверяем брони и остатки;
   - создаём заказ (`created`), списываем брони, ставим `confirm_until`;
   - пишем смену статуса (потом в `GET /orders/{id}` как `status_history`);
   - уведомляем заведение, не дольше 2 секунд.
4. Дальше confirm / reject / отмена пользователем или по дедлайну.

Проверка может устареть. Создание заказа всегда проверяет заново.

`invalid_items.reason`: `reservation_expired`, `out_of_stock`, `dish_inactive`.  
`blockers`: `restaurant_closed`, `below_min_order`, `empty_cart`.

## Бронь сгорела между проверкой и заказом

При создании берём только живые брони (`active`, время не вышло). Мёртвая — в `invalid_items` с `reservation_expired`.

## Два запроса с одним ключом

Ключ привязан к заказу. Второй запрос с тем же ключом возвращает тот же заказ и ничего не списывает.

## Частичный заказ, пока думали пропало ещё блюдо

Снова полная проверка. Смотреть на ответ создания, не на старый validate.

## Заведение не ответило за 2 секунды

Заказ уже в базе. Пользователю не 500: статус `pending_confirmation`. Отмена ещё можно. Заведение потом само запросит список.

## Дедлайн 15 минут

Заказ `created` / `pending_confirmation` и `confirm_until` вышел → `cancelled`, остаток на склад. Смотрим это в `GET /orders/{id}` и `GET /partner/orders`. Поздний confirm — `409`.

## Два человека на последнюю порцию

В транзакции блокируем строку блюда и считаем свободный остаток. Кому не хватило — нет в наличии. То же при увеличении qty в `PATCH`: не хватает — `409`, старое количество не трогаем.

## Отмена

Из `created` / `pending_confirmation` — да, остаток возвращается. С `confirmed` и дальше — `409`.

## Ресторан отклонил

Статус `rejected`, запись в историю, остаток на площадке возвращаем.

В демо сверка с локальным стоком в памяти. Склады могут разъехаться. Нет порций у кухни — reject. Обновить площадку: `PUT /partner/menu` или `PATCH /partner/dishes/{externalId}`.

## Блюдо из другого заведения

Не смешиваем, `409`. Сначала `DELETE /cart`.

## Блюдо сняли с меню

`is_active = false` — не то же самое, что `stock_qty = 0`. Живые брони снимаем сразу, в validate будет `dish_inactive`, кэш витрины сбрасываем.

## Плохой запрос

qty ≤ 0, нет блюда, нет `external_id` у partner — `400` или `404`, не `500`. Пустой каталог и пустое меню — `200`.

## Адрес доставки

`delivery_address` в `POST /orders` — строка для статуса «в доставке». Курьера нет.

## Redis недоступен

Каталог читаем из Postgres, не 500. Бронь и заказ Redis не используют.

Кэш сбрасываем при записи партнёра. `available_qty` всегда из Postgres.
