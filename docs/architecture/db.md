# Схема базы данных

Картинка: [er.puml](er.puml). SQL: [migrations/000001_init.up.sql](../../migrations/000001_init.up.sql).

Остатки и брони хранит **площадка** (Postgres). Redis таблиц не добавляет: там только копия витрины каталога, см. [design-decisions.md](../design-decisions.md). Заведение присылает меню и stock. У `partner-demo` своя копия стока живёт в памяти процесса, не в отдельной БД.

## Таблицы

| Таблица | Зачем |
|---------|--------|
| `restaurants` | Заведение на площадке: название, кухня, открыто ли, минимальная сумма, URL и ключ партнёра |
| `menu_categories` | Разделы меню |
| `dishes` | Блюдо. `external_id` — id у заведения. `stock_qty` — сколько на складе. `is_active` — не снято ли с меню совсем |
| `carts` | Одна корзина на пользователя (`user_id` уникален), сразу привязана к одному заведению |
| `cart_items` | Позиции корзины |
| `dish_reservations` | Бронь на время: `expires_at`, статус `active` / `expired` / `consumed` / `released` |
| `orders` | Заказ. `status` — текущее состояние. `confirm_until` — до какого момента ждём подтверждение. `delivery_address` — строка для отображения, не логистика курьера |
| `order_items` | Состав заказа. Имя и цена **скопированы**, потому что меню потом изменится |
| `order_status_history` | Кто и когда сменил статус. Читается в `GET /orders/{id}` как массив `status_history` (отдельный роут не нужен) |
| `idempotency_keys` | Чтобы повторный «Оформить» с тем же ключом не создал второй заказ. `request_hash` в схеме есть, в MVP не заполняем |

## Правила и поля

- **Свободный остаток** = `dishes.stock_qty` минус сумма живых броней (`status = active` и `expires_at > now()`).
- **Одна корзина — одно заведение** = уникальный `carts.user_id` + `restaurant_id` у этой корзины.
- **Блюдо сняли с меню** = `dishes.is_active = false`, живые брони на него отпускаем.
- **Ждём заведение ограниченно** = `orders.confirm_until`. Если время вышло, а статус ещё `created` или `pending_confirmation` — заказ `cancelled`, остаток возвращаем.
- **Отмена пользователем** разрешена в `created` / `pending_confirmation`. С `confirmed` и дальше — нельзя.
- **Количество** в `cart_items` всегда > 0. Блюдо должно принадлежать заведению корзины. Уменьшение qty отпускает бронь; увеличение бронирует разницу или даёт `409`.
- **`available_qty` в меню** всегда из этих полей, не из Redis.

Причины и блокеры проверки корзины — не колонки, а значения API:  
`reservation_expired` / `out_of_stock` / `dish_inactive` и `restaurant_closed` / `below_min_order` / `empty_cart`.
